# Context Pilot 常见问题

## 什么是 KV Cache？

大模型推理时，每生成一个 token 都要对之前所有 token 做注意力计算。KV Cache 把这些中间结果缓存下来：如果新一轮请求的上下文前缀和上一轮完全一致，就可以直接复用缓存，只计算新增部分，大幅降低延迟和算力开销。一旦前缀发生任何变化（例如历史被删除、摘要、裁剪，或 System Prompt 修改），缓存就会失效，需要重新计算。

## 上下文窗口满了会发生什么？

传统做法是直接截断最早的内容，这会丢失信息。Context Pilot 提供三种策略：删除历史（最快但信息全丢）、摘要压缩（保留意图丢失细节）、智能裁剪（按相关度+新近度打分，裁掉低价值内容，最精准但需要额外计算）。

## RAG 为什么能提升回答质量？

RAG（检索增强生成）在用户提问时先从知识库中检索相关片段，把检索结果注入上下文，再让模型基于这些内容回答。这样模型可以引用最新的、私有的知识，而不依赖训练语料，同时减少幻觉。

## MCP 是什么？

MCP（Model Context Protocol）是连接大模型与外部工具/数据源的标准协议。通过 MCP，模型可以调用地图、数据库、搜索引擎等外部能力，调用请求与返回结果都会进入上下文。

## Token 如何估算？

Context Pilot 使用本地启发式估算：中文约 1 字 = 1 token，英文约 4 字符 = 1 token，另加每条消息的结构开销。该估算与 Qwen/GLM 系分词器接近，适合演示场景。
